# ResearcherOS StarterKIT: правила работы агента

Это учебный набор для первого исследования, а не соревнование Kaggle. Прогнозируется числовая колонка `wCTR (%)`, не метка наличия клика.

Перед работой прочитай `data/README.md` и `data/protocol.json`. Инструкции платформы ResearcherOS о создании дерева, карточках, отчётах и выводах продолжают действовать.

- Данные `data/advertising.csv` и протокол `data/protocol.json` не изменяй. Проверяй их командой `python scripts/check_data.py`.
- Признаки перечислены в протоколе; `row_id` и целевая колонка не входят во вход модели. Обработку признаков обучай только на train.
- Основная метрика - RMSE. Первое сравнение: средний прогноз против дерева глубины 3 с `min_samples_leaf=20`, `random_state=42`. Остальные параметры явно запиши в отчёте.
- До прогона зафиксируй правило: снижение проверочной RMSE не менее чем на 1% относительно исходного решения. Отрицательный результат допустим. Сбой запуска не является опровержением гипотезы.
- До заключительного этапа шага 8 не вычисляй, не показывай и не используй метрики test. Исследуй train и validation. Файл содержит test физически; не используй его для подсказок.
- Стартовый бюджет - CPU, без GPU и удалённых серверов. Не устанавливай облачные услуги и не запускай платные вычисления. Подписка или API выбранного CLI-агента оплачиваются пользователем отдельно.
- Каждый запрос Arbor имеет собственный предел: не более 15 минут и двух экспериментальных запусков, по одному одновременно. Согласуй настройки окна запуска с этим пределом. Оставь время на отчёт. Не начинай следующий запрос автоматически.
- Не запускай эксперимент до завершения постановки карточки. Веди реальные статусы, подзадачи, журнал и монитор. Не создавай фиктивные результаты и графики.
- Результаты сохраняй в `runs/<имя-запуска>/`: команда, конфигурация, версия библиотек, метрики, предсказания и изображения. Не перезаписывай прошлые прогоны.
- Дерево, отчёты и выводы храни в месте, которое настроил ResearcherOS; не создавай параллельное дерево внутри репозитория.
- В исходном репозитории только `main`; не создавай веток и worktree в этом кодовом репозитории. Если Arbor нужны изолированные каталоги, используй независимые копии без новых веток.
- При редактировании отчёта сохраняй числа, ограничения, критерий решения и изображения. Словарь меняй только для этого дерева, если человек не попросил общего правила.
